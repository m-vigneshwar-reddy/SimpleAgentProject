CustomerChurnPredictor

This package contains a lightweight, rule-based customer churn analyzer and a small sample dataset. It is intended as a reference utility and demo for producing human-readable churn risk reports and machine-friendly outputs (JSON and CSV).

**What’s in this folder**
- `churn_analyzer.py`: Core analyzer logic. Loads the sample CSV, computes risk signals and classifications, prints narrative reports, and writes JSON + CSV outputs to the `reports/` folder.
- `data/customers.csv`: Example input dataset (CSV). Each row is a customer record with fields used by the analyzer.
- `reports/`: Output directory where `churn_reports.json` and `churn_reports.csv` are written after a run.
- `pyproject.toml`: Package metadata to allow installing or exposing a console entrypoint (`churn-analyze`).
- `__init__.py`: Package marker.

How the analyzer works (high level)
- Input: reads `data/customers.csv` and parses rows into dictionaries.
- Signal extraction: converts numeric fields and derives signals such as engagement decay, support spike, payment/contract health, and value disconnection.
- Scoring: applies simple rule-based heuristics to count major flags and map them into a `risk_classification` (Low/Medium/High), a numeric churn probability, and a time horizon.
- Report generation: for each account the analyzer builds a structured report including core drivers, a behavioral summary, and recommended playbook actions.
- Output: prints human-readable reports to stdout, writes `reports/churn_reports.json` (detailed structured output) and `reports/churn_reports.csv` (summary rows suitable for BI ingestion).

Step-by-step process (what happens when you run the analyzer)
1. `run_churn_analysis.py` (repository root) imports and calls `CustomerChurnPredictor.churn_analyzer:main()`.
2. `churn_analyzer.main()` checks `CustomerChurnPredictor/data/customers.csv` and parses it with `csv.DictReader`.
3. For each record, `analyze_account()` computes signals and flags using the following checks:
	- Engagement decay: compares `logins_30d` vs `logins_7d` to detect sharp drops.
	- Support friction: counts `support_tickets_30d` and `unresolved_tickets`, evaluates `ticket_sentiment_neg_pct`.
	- Account health: inspects `payment_status`, `last_payment_date`, and `contract_end_date`.
	- Value disconnection: compares `spend_30d` vs `feature_adoption_score`.
4. The analyzer aggregates these signals into `major_flags` and determines `risk_classification`, `churn_probability_percent`, and `time_horizon`.
5. A narrative `behavioral_summary` and `playbook` (trigger, value intervention, commercial safeguard) are composed from the dominant signals.
6. All reports are collected, written to JSON and CSV, and printed to the console.

Running the analyzer
From the repository root run:

```bash
python run_churn_analysis.py
```

Or, after installing the package (optional) you can run the console script:

```bash
pip install -e .
churn-analyze
```

Outputs
- `CustomerChurnPredictor/reports/churn_reports.json`: structured list of report objects (rich fields and signals).
- `CustomerChurnPredictor/reports/churn_reports.csv`: single-row-per-customer summary suitable for spreadsheets or BI tools.

Extending or customizing
- To add more signals, edit `analyze_account()` in `churn_analyzer.py` and append new `signals` tuples.
- To change scoring, adjust the `major_flags` calculation and the mapping to `risk_classification` and `churn_probability`.
- To support additional input formats, add parser functions (e.g., a database connector) and feed parsed dicts into the existing `analyze_account()` pipeline.

Notes and caveats
- The analyzer is rule-based and intended for demonstration. For production use, validate input data quality and consider a statistical or ML-based approach.
- Dates are parsed using `YYYY-MM-DD`; missing or invalid dates default to safe fallbacks.
